1. **Fixed, not a game bug.** `scripts/walk14.mjs` used to wait 1500 ms and then call `wipe`. On a cold server the first width threw `Cannot read properties of undefined (reading 'wipe')` and every combined row came back fail. The second width, same binary, passed. That commit is `adcc32a`, by G, one line.

2. **Minor. The tier filter does not hide the open lesson.** `GameApp.tsx` 2037–2101 filters the title list and the next/prev step. The body underneath stays `ACADEMY[index]` even when that page is another tier. Step 7 does not use the filter. The tier label and the existing ALARA quiz are what the step checks.

4. **Minor. A reload before a pass drops the Core Map.** `ReactorApps.tsx` writes `s.results.coreMap` on every swap. `writeSave` runs from `onResults`, and that callback fires on a pass (`GameApp.tsx` 1667–1670). Reopening the window in the same session keeps the grid. The walk checked that, and `shuffleDone` stayed false. That matches the rule that only a pass writes the save.

5. **Minor. The PR body says zero page errors. The warm re-run logged four console lines per width: "Failed to load resource: 403".** Vite did not log a 403. A boot-only capture logged no 4xx. I could not tie the lines to a game URL. The rows still passed. The known `window is not defined` server-render line is filtered by the driver and is the old one.
