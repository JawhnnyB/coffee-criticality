**R2. B3 calls a red audit an expected result.** The overflow audit counts `shortButtons` as violations (`scripts/overflow-audit.mjs` lines 60 and 167). At 390 wide the run logs 32 on Settings, 9 on Academy, 2 on Music, and 1 on Radiation. That is 44 buttons under 44px on four screens. The row says the nonzero exit "is expected." By the audit's own rule it is not. The 44px minimum comes from my breakdown's proposed Part 5. It is not in `GROK_PHASES_1-4.md` or in `tools/artkit/STYLE-STANDARD.md`. Either fix the buttons, or the owner decides that minimum does not apply (D11). Until then, B3 passes for naming only, and the row must say the audit is red and give those counts.

**R3. The keyboard evidence is narrower than the row says.**
- Tests 1 to 4 run `keyGate.ts` through a `step()` model that the test itself defines. Nothing in them runs `DelayGame`, `GameApp`, or any other listener.
- Tests 5 and 6 check that source files contain the text `hostOwnsKey(` (and `readHeld(` in four files). Removing one listener's gate call passes if the file has another call. `GameApp.tsx` is checked for one specific line.
- The test prints `static-focus moved 0`, `mini-focus world-x stay 40`, `mini-focus mini-x 41`, and `KEY_GATE_CASES 4` with literal `console.log` calls. Those are not measurements. The exit code proves only that the earlier assertions passed.

Required: print computed values from the code under test. Then either drive the real listeners (the Playwright driver, or a DOM test), or change the row to "gate function tested; listener wiring checked by text only." Keep "not walked in a browser" in the row.

**R4. `scripts/teaching-lab.test.mjs` needs the network.** It calls `npx esbuild` directly and ignores the `ESBUILD` variable. Spec 14.1 says to use that pattern and not rely on `npx` reaching the network. The test is already on `main`, so this PR did not add it. Offline, it fails, which is why this environment shows ten failures and not nine. Switch it to the `ESBUILD` pattern used in `shuffle-model.test.mjs`. That is a plumbing change, not a weakening. Then the baseline reproduces offline, or the baseline file records that it was taken online.

**R5. Commit an unscrolled 1280×720 Reactor Design still.** `builder-1280x720.png` is scrolled to the bottom of the panel. The speaker card and portrait sit above the visible area. B2's claim is true, but the first view a player sees is not in the evidence. Add a still of that first view, and name the still that proves the legend.

**R6. Check whether the world moves behind an open cabinet while the desk is closed.** `hostOwnsKey("world")` and `hostOwnsKey("mini")` both return true when the owner is `world`. The status note says this is intended ("a full-screen cabinet still hears keys"). The world listener in `GameApp.tsx` line 256 also accepts the key in that state. The code I read does not show whether the world loop pauses while a cabinet is open. Open a cabinet from the cafe with the desk closed, hold a movement key, and check the player does not move behind it. If the player does move, pause the world listener while a cabinet is open, and add a test that asserts it.
