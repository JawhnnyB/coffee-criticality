## Findings

1. **Blocking.** `peekSave` deletes a v2 save that fails to parse (save.ts line 205–206, `localStorage.removeItem(SAVE_KEY_V2)`), and returns null. The v1 key is still present, so the next load migrates the older v1 save. The player's newest data is removed silently, and an older save comes back in its place. Fix: keep the corrupt value under another key (for example `cc.save.v2.corrupt`) instead of removing it, and do not fall back to v1 while a v2 key exists. Add a test that a corrupt v2 is preserved and that v1 is not used in that case.
2. Non-blocking. The v1 catch block no longer wipes the save (save.ts line 219). That is correct, and it is an improvement over main.
3. Non-blocking. wipeSave clears both keys (save.ts lines 230–231). That is the intended behavior for a new shift.
4. Non-blocking. `tiersFromDone` returns tier 1 for every page. That is the documented placeholder until the tiers exist.

## Verdict reason

The migration and the non-overwrite rule are correct, and the test uses the real v1 fixture. The one blocking issue is that a corrupt v2 save is deleted and an older v1 save can come back in its place. That is a data-loss path in the save code, and it needs a fix and a test before merge.
